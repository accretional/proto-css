# CLAUDE.md — proto-css-new

## What this project is

A visual reference for CSS properties. Each of the 525 CSS properties in `properties.txt` gets an HTML template that demonstrates the property with live examples, then Chrome screenshots them into PNGs, and a gallery page aggregates everything.

The project is designed to grow into a proto-based Go service (gRPC + gateway + OpenAPI) — the script scaffolding is already in place for that.

## Project structure

```
properties.txt                 # Master list of 525 CSS properties (one per line)
templates/                     # Standalone HTML templates (subset, 47 files)
chrome-testing/
  templates/                   # Full set of HTML templates (525 files, one per property)
  screenshots/                 # PNG screenshots taken by snap.sh
  gallery.html                 # Generated gallery page (built by run.sh)
  snap.sh                      # Takes HTML files → PNG screenshots via chromerpc
  run.sh                       # Screenshots all templates + generates gallery.html
  USAGE_INSTRUCTIONS.md        # Docs for the chrome-testing module
third_party/                   # Third-party proto definitions (googleapis, grpc-gateway)
tools/gen.sh                   # Proto code generation script
embed/                         # Staged embedded assets (gallery + screenshots for Go embed)
```

## Development rules

**No one-off commands.** All tests, builds, and setup steps MUST go through scripts:

| What | Command |
|---|---|
| Setup | `./setup.sh` |
| Code generation | `./tools/gen.sh` |
| Build | `./build.sh` |
| Test | `./test.sh` |
| Full pipeline + browser | `./LET_IT_RIP.sh` |

If something needs to be tested or built, it belongs in a script. If it's not in a script, it doesn't count as tested.

Quick `go build ./...` or `go vet ./...` during development to catch compile errors is fine, but **final validation before committing must ALWAYS go through the scripts**.

**CRITICAL: ALWAYS run `./LET_IT_RIP.sh` before EVERY `git commit` and `git push`.** No exceptions. The embedded build/test logs, generated HTML, and smoke tests all depend on this pipeline running to completion.

## Script behavior

- Scripts are **idempotent** — safe to re-run at any time.
- They kill old servers on their ports before starting.
- They clean up on exit (trap EXIT).
- They work correctly when re-run without manual intervention.
- Never fix things with one-off commands outside the scripts — always update the script and rerun it.

## HTML templates

- Each template is a self-contained HTML file named `{property-name}.html`.
- Templates use a dark theme (`#1a1a2e` background) with monospace code labels.
- They demonstrate the CSS property with multiple value variations in a card/grid layout.
- Templates must start with `<!DOCTYPE html>` (validated by test.sh).

## Screenshots

- Taken at 1280x800 viewport, 2x device scale factor.
- chromerpc (headless Chrome via gRPC) handles the actual capture.
- chromerpc is auto-built from source and cached in `/tmp/chromerpc-testing/`.

## Port conventions

- `LET_IT_RIP.sh` gallery server: port 8888 (override with `SERVE_PORT=`)
- chromerpc and HTTP servers in snap.sh: auto-assigned free ports

## Prerequisites

- Go (for chromerpc build and future project code)
- Google Chrome (for headless screenshots)
- Python 3 (for local HTTP serving)

## Code generation (future)

When proto files are added to `proto/`:
- `tools/gen.sh` generates Go + gRPC + gateway + OpenAPI code into `gen/`
- Uses `protoc` directly, or `buf generate` if `buf.gen.yaml` exists
- Third-party protos live in `third_party/` (cloned by setup.sh)

## Things to NOT do

- Do not run `go test` directly as final validation — use `./test.sh`.
- Do not commit without running `./LET_IT_RIP.sh`.
- Do not fix things with one-off commands — update the relevant script.
- Do not manually edit `gallery.html` — it is generated by `run.sh`.
- Do not modify screenshots manually — they are generated by `snap.sh`.
