# CLAUDE.md — proto-css-new

## Development rules

**No one-off commands.** All tests, builds, and setup steps MUST go through scripts:

| What | Command |
|---|---|
| Setup | `./setup.sh` |
| EBNF to HTML generation | `./tools/gen.sh` |
| Build (screenshots + galleries) | `./build.sh` |
| Test | `./test.sh` |
| Full pipeline + browser | `./LET_IT_RIP.sh` |

If something needs to be tested or built, it belongs in a script. If it's not in a script, it doesn't count as tested.

Quick `go build ./...` or `go vet ./...` during development to catch compile errors is fine, but **final validation before committing must ALWAYS go through the scripts**.

**CRITICAL: ALWAYS run `./LET_IT_RIP.sh` before EVERY `git commit` and `git push`.** No exceptions.

## Script behavior

- Scripts are **idempotent** — safe to re-run at any time.
- They kill old servers on their ports before starting.
- They clean up on exit (trap EXIT).
- They work correctly when re-run without manual intervention.
- Never fix things with one-off commands outside the scripts — always update the script and rerun it.

## HTML templates

- Hand-written templates live in `chrome-testing/html/template/`, one per CSS property.
- Generated templates live in `chrome-testing/html/generated/`.
- The master list of properties is `chrome-testing/properties.txt` (525 entries).
- Each template is a self-contained HTML file named `{property-name}.html`.
- Templates use a dark theme (`#1a1a2e` background) with monospace code labels.
- They demonstrate the CSS property with multiple value variations in a card/grid layout.
- Templates must start with `<!DOCTYPE html>` (validated by test.sh).

## EBNF generation

- 12 EBNF grammar files in `lang/` define CSS value syntax (~3900 rules).
- `chrome-testing/cmd/generate/` parses grammars and generates CSS values.
- Generated HTML clones hand-written templates with grammar-derived values swapped in.
- Run via `./tools/gen.sh` or `./chrome-testing/run_gen.sh`.

## Screenshots

- Taken at 1280x800 viewport, 2x device scale factor.
- chromerpc (headless Chrome via gRPC) handles the actual capture.
- chromerpc is auto-built from source and cached in `/tmp/chromerpc-testing/`.

## Port conventions

- `LET_IT_RIP.sh` gallery server: port 8888 (override with `SERVE_PORT=`)
- chromerpc and HTTP servers in snap.sh: auto-assigned free ports

## Prerequisites

- Go (for chromerpc build and EBNF generator)
- Google Chrome (for headless screenshots)
- Python 3 (for local HTTP serving)

## Things to NOT do

- Do not run `go test` directly as final validation — use `./test.sh`.
- Do not commit without running `./LET_IT_RIP.sh`.
- Do not fix things with one-off commands — update the relevant script.
- Do not manually edit gallery HTML files — they are generated by `run.sh` / `run_gen.sh`.
- Do not modify screenshots manually — they are generated by `snap.sh`.
