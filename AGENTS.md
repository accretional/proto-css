# AGENTS.md — Agent guidelines for proto-css-new

## General rules for all agents

1. **Scripts are law.** Never run one-off build/test/setup commands. All work flows through:
   - `./setup.sh` — install toolchain, download protos, tidy modules
   - `./tools/gen.sh` — regenerate proto code (Go, gRPC, gateway, OpenAPI)
   - `./build.sh` — screenshots, gallery, embedded source, Go binary
   - `./test.sh` — vet, test, build-check, template validation, smoke-test
   - `./LET_IT_RIP.sh` — full pipeline + serve + browser open

2. **Always run `./LET_IT_RIP.sh` before committing or pushing.** No exceptions. If you're unsure whether it was run, run it again.

3. **Scripts must stay idempotent.** If you modify a script, ensure it:
   - Kills old servers on its ports before starting
   - Cleans up on exit (trap EXIT)
   - Works correctly when re-run without manual intervention

4. **Never fix things outside scripts.** If a build step is broken, fix the script and rerun — don't patch around it with manual commands.

5. **Quick `go build ./...` or `go vet ./...` is fine during development** to catch compile errors fast. But the final validation before any commit must go through `./test.sh` or `./LET_IT_RIP.sh`.

## Working with HTML templates

- Templates live in `chrome-testing/templates/`, one per CSS property.
- The master list of properties is `properties.txt` (525 entries).
- Each template must be a valid standalone HTML file starting with `<!DOCTYPE html>`.
- Template naming convention: `{css-property-name}.html` (kebab-case matching the property name exactly).
- Templates use a dark theme with card-based layouts showing multiple value demonstrations.
- Do not hand-edit `gallery.html` — it is generated by `chrome-testing/run.sh`.

## Working with screenshots

- Screenshots are generated by `chrome-testing/snap.sh` via headless Chrome (chromerpc).
- Viewport: 1280x800, 2x device scale. Output: PNG.
- chromerpc is auto-built and cached at `/tmp/chromerpc-testing/`.
- To regenerate all screenshots, run `./build.sh` (which calls `chrome-testing/run.sh`).
- To regenerate only the gallery from existing screenshots: `./chrome-testing/run.sh --gallery-only`.

## Working with proto / Go code (future)

- Proto files go in `proto/`.
- Generated code lands in `gen/go/` (Go + gRPC + gateway) and `gen/openapi/` (OpenAPI specs).
- Third-party protos (googleapis, grpc-gateway) are in `third_party/`, managed by `setup.sh`.
- Run `./tools/gen.sh` after any `.proto` file change.
- Run `./setup.sh` if proto toolchain seems missing or outdated.

## Port conventions

| Service | Port | Notes |
|---|---|---|
| Gallery server (LET_IT_RIP.sh) | 8888 | Override with `SERVE_PORT=` env var |
| chromerpc (snap.sh) | auto | Free port per run |
| HTTP file server (snap.sh) | auto | Free port per run |

## Adding a new script or build step

If you need a new build/test/setup step:
1. Add it to the appropriate existing script (`setup.sh`, `build.sh`, `test.sh`, `tools/gen.sh`).
2. If it's truly a new phase, create a new script and wire it into `LET_IT_RIP.sh`.
3. Ensure the new step is idempotent, cleans up after itself, and exits non-zero on failure.
4. Run `./LET_IT_RIP.sh` to verify the full pipeline still works end-to-end.

## Commit checklist

Before every commit and push:
- [ ] `./LET_IT_RIP.sh` ran to completion with no failures
- [ ] `test.sh` reported all checks green
- [ ] No manually-run one-off commands were used as final validation
- [ ] Any new build/test steps were added to the appropriate script
